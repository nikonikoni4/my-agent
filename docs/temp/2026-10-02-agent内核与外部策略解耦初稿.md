# Agent 内核与外部策略解耦初稿

日期：2026-10-02。状态：架构方向初稿，尚未落实为代码或正式契约。

## 背景与目标

myagent 需要作为独立模块导入其他项目。使用方可能已有 provider、异常体系和恢复策略；若框架要求使用自身 provider、供应商错误分类或固定重试策略，会造成重复处理和接入耦合。

目标是保留 agent loop 的执行主框架，通过明确的调用契约、事件契约和控制决策契约接入外部实现，同时保持错误现场可观测、控制动作可约束、失败路径可收尾。

## 已确认的方向

### 1. 内核不解释外部错误的业务含义

外部组件产生的异常类型、业务含义和恢复规则由使用方定义。内核不依赖具体 SDK 异常，也不要求外部异常继承框架的 LLM 异常分类树。

内核仍负责捕获执行边界上的错误，记录异常及现场，并通过错误决策事件交给订阅方。内核知道错误发生的阶段及执行进度，但不据外部异常类型决定是否重试、切换模型或进行业务降级。

用户表述：

> 外部触发的错误，agent内部并不知道，也不需要知道。只需要他们写的相关策略接口能够订阅事件自己接住。

### 2. 外部策略认领错误，内核执行控制决策

使用方注册策略处理器，订阅错误决策事件，识别自己负责的错误并返回决策；未认领时交给后续处理器。

“接住错误”指认领并返回处理意图。策略不能通过直接修改 loop 内部状态来绕过控制契约。循环控制、预算变更、重试等待和过程记录由内核统一落地。

```text
执行边界捕获错误
    → 记录错误现场
    → 发布错误决策事件
    → 外部订阅方认领并返回决策
    → 内核校验决策
    → 内核执行动作并记录结果
```

### 3. 控制动作集合固定，返回类型严格约束

内核只接收固定类型的控制决策，不接受任意字符串或任意形状的 dict。动作集合由内核契约定义；参数允许在契约规定的范围内配置。

用户表述：

> 内部能够对loc控制反转能够采取侧策略需要完全约束，返回一个固定的type，只接收固定的控制策略。

增加错误匹配规则或更换恢复策略只需替换外部实现；增加一种新的 loop 控制动作，需要扩展内核契约及执行逻辑。

Protocol 用于表达接口和静态类型约束；运行时仍需要校验外部决策，避免非法值进入状态变更。具体类型名称、字段和动作枚举尚未确定。

### 4. 框架自身错误与约束保留

内核保留由自身机制产生的错误，例如步数上限、工具熔断，以及执行控制所需的预算和取消约束。

内部错误类型和具体处置策略分离：框架定义并产生错误，策略根据契约表达继续、重试或终止等意图，内核判断参数是否合法并执行。内置策略的保留范围、默认装配方式及是否允许替换，仍需细化。

用户表述：

> 框架内完全解耦（除了内部定义的策略错误：最大上限步骤和熔断，以及他们的策略）。

### 5. 具体 provider 与业务策略移出内核

provider 的具体实现、SDK 调用、供应商异常分类和项目恢复策略归使用方或可选集成层。当前 OpenAIProvider、LLMRetry 等实现不应成为内核运行的强制依赖。

模型调用接口可以用 Protocol 表达。内核仍需拥有自己消费的输入输出契约，例如消息、流片段、模型结果和工具调用数据。使用方可以直接满足契约，也可以通过适配器转换。

统一插件注册方式不等于所有扩展点共用一个万能 Protocol。各扩展点应明确自身输入输出；错误决策处理器可以共享一种契约，其他扩展点是否需要独立契约按实际语义确定。

## 职责边界

| 内容 | 归属 |
| --- | --- |
| agent loop、执行编排、会话及 trace | 内核 |
| 模型调用与事件输入输出契约 | 内核 |
| 固定的控制决策类型、参数校验及执行 | 内核 |
| 步数上限、熔断等框架自身错误 | 内核 |
| provider、SDK、供应商响应转换 | 外部实现或可选集成层 |
| 外部异常类型、业务含义及匹配规则 | 使用方 |
| 重试、切模型、上下文治理及人工介入策略 | 外部策略，通过契约与内核协作 |

## 需要保住的执行语义

以下是落地时需要明确的约束，不代表所有具体行为已定稿：

- 取消保持独立传播，不作为普通恢复策略处理。
- 外部异常进入错误决策链时保留原始异常及因果链。
- 流中途失败也需要保留已有输出并补齐失败现场，不能仅依赖 LLMCallError 类型完成收尾。
- 无人认领、决策非法、策略自身失败必须有明确的终止和记录规则；不能无限进入同一错误处理链。
- 必须定义重试的执行范围，区分再次调用模型与重新执行整个 step，避免重复执行已有副作用的工具。
- provider 内部恢复与 loop 恢复需要约定责任及预算，避免两层重试无意叠加。若外部隐藏内部尝试，内核 trace 的观测范围也需明确。

## 与当前实现的差异

当前代码已有事件订阅及策略决策与 loop 执行分离的基础。此次方向是在此基础上进一步解除对具体 provider 和外部错误分类的依赖，并收紧决策类型。

- `src/myagent/agent/core/provider.py`：当前包含 LLMProvider 抽象基类及 OpenAI 风格工具响应提取；接口与供应商转换职责需要分开。
- `src/myagent/agent/llm/openai_provider.py`：具体 SDK 实现及错误分类，拟移至外部或可选集成层。
- `src/myagent/agent/llm/llm_retry.py`：当前按框架 LLM 异常类型匹配固定重试规则，拟改为可选外部策略实现。
- `src/myagent/agent/core/agent/loop.py`：当前消费 dict 决策，模型流失败补齐依赖 LLMCallError；后续需要对齐固定决策类型及外部异常边界。

本初稿不修改现有 ADR，也不表示上述迁移已完成。

## 待细化事项

1. 模型调用 Protocol 的最小接口及流式输入输出契约。
2. 错误事件上下文的字段：阶段、调用标识、部分输出及工具执行进度等。
3. 决策类型的动作集合、各动作参数及非法决策的处理规则。
4. 多订阅方的认领顺序、委托规则及默认兜底。
5. 框架内部错误对应策略的默认值、覆盖方式及装配位置。
6. 重试范围、预算归属及外部 provider 内部尝试的观测边界。
7. 熔断机制与可配置策略的具体分界。
8. 现有实现的迁移路径、可选集成包位置及兼容范围。
