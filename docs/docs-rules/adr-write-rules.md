# adr-write-rules

## 1. 定位

ADR 与 `docs/adr/user-design-summary.md` 是后续 agent 做自主决策的依据（见 CLAUDE.md 的 docs-read-rules 第 8 条）。写错一条，就会被后续 agent 当作"用户已决定"沿用下去，且很难被发现。

因此本规则的核心是：**ADR 里的每条决策，都必须能追溯到用户说过的一句话。**

## 2. 写入规则

### 2.1 决策必须逐条列出

「最终决策」章节用编号列表，**一条 = 一个可独立判断取舍的决定**。

- 禁止把多条决定塞进一段话或一个 bullet——那样既无法逐条核对依据，也无法单独标注失效条件。
- 每条决策应与「决策逻辑」表中的一行、或一条"前提失效时的切换"对应。

### 2.2 每条决策必须附用户原话作为依据

格式（紧跟决策条目）：

```md
- 决策 1：[一条可独立判断的决定]
  - 依据（用户原话）：「[用户消息中的原话]」
```

- 引号内必须是**用户消息里的原话**：可截取片段，不得改写措辞、不得把不同轮次的话拼接成一句、不得把 AI 的复述当成用户的话。
- **找不到原话支撑的条目，不写进「最终决策」。**

### 2.3 以下来源只能作参考，不能作为依据

| 来源 | 能否作依据 | 说明 |
| ---- | ---------- | ---- |
| 用户消息中的原话 | ✅ 唯一合法依据 | 逐字可查 |
| 通过工具（AskUserQuestion 等）向用户抛出的选项、以及用户在选项中的勾选 | ❌ | 用户可能无法在短时间内审核到位，选项措辞由 AI 拟定，不构成用户的明确表态，只能作为**待确认的参考线索** |
| AI 自己的推理、类比、"更一致 / 更简洁 / 更可维护"之类的工程判断 | ❌ | 可写进「可选方案 / 决策原因」作为候选，但不得以既成事实的口吻写进「最终决策」 |
| 代码现状（"代码已经这么写了""实现方已落地"） | ❌ | 实现不是决策 |
| 其他文档里 AI 写过的话 | ❌ | 自引用不是依据 |

判定动作：想引用某条依据时，先问自己"这句话是**用户在消息里亲手打的**吗？"——不是，就只能放进参考区。

### 2.4 不确定时必须询问用户；宁可不写，也不能错写

- 无法定位某条决策对应的用户原话时：**停下来问用户**，不要替用户补一句。
- 用户未回答或拒绝回答：该条从「最终决策」删除；若确需留档，只能写成 `未决（待用户确认，非决策）`。
- 判据：ADR 中任何一条被后续 agent 引用的决策，都必须能指向用户说过的一句话。指向不到 → 宁可让文档少一条。

### 2.5 实现方自主做出的决定怎么记

实现方（AI）在落地时自行做出的选择，若用户尚未表态：

- 写在 `已接受的实现选择 / 未决项` 一节，**显式标注"非用户决策"**；
- 不得混入「最终决策」，也不得写进「决策原因 / 决策前提」当作论据。

### 2.6 修订已有 ADR 时

- 新增或改写任何一条决策，同样适用 2.2：先拿到用户原话再落笔。
- 撤销/修正原属 AI 擅作主张的条款时，在「演进历史」里显式记录撤销动作与新版本（保留原版本行，不抹掉历史）。

### 2.7 沿用既有 ADR 结构

每份 ADR 保持本仓库现有章节顺序：问题界定 → 现状 → 决策前提 → 可选方案 → 决策逻辑 → 演进历史 → 最终决策 → 决策原因 → 后续影响。本规则只约束其中「决策从哪来、怎么写」，不改结构。

## 3. 写前 / 写后检查清单

- [ ] 「最终决策」每条都编号，且一条一个可独立判断的决定
- [ ] 每条决策后都有 `依据（用户原话）：「…」`
- [ ] 每句原话都能在用户消息里逐字找到（未被改写、未被拼接）
- [ ] 没有把工具选项、AI 推理、代码现状、其他文档当成依据
- [ ] 每条决策与「决策逻辑」表的失效切换条件对应
- [ ] 拿不到原话的条目已删除或标为"未决（非决策）"，而不是被补写出来
- [ ] AI 自主做出的选择已单独标注"非用户决策"

## 4. 反例（本仓库实例，务必读）

2026-09-15《session 错误信息记录策略》v3：实现方在 loop 错误处理重构（提交 `74ab0f8`）中，把「`llm/retry` 覆盖"决定不重试 / 重试耗尽"两个收尾出口」写成了已定决策，并在 ADR 与 user-design-summary 中标注为用户的选择——**用户从未做过这个决策**。该写法同时造成 `llm_retry_count` 被非重试的失败虚增（重试次数按 `llm/retry` 记录条数统计）。已于 2026-09-17 升级为 v2.0 撤销，详见该 ADR 的「演进历史」v4 与「防御性说明」。

## 5. 禁止事项

<never_do>

1. 不得把用户没说过的结论写进「最终决策」。
2. 不得用工具询问得到的选项（或用户在其中的勾选）当决策依据。
3. 不得为了让文档"完整/自洽"而补写决策——宁缺勿错。
4. 不得为了让已有结论成立而改写、裁剪用户原话；措辞上的任何调整都必须在演进历史中显式记录。

</never_do>
