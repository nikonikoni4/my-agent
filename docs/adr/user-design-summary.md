## 决策偏好总结

- **原则先行推导架构决策**：概念层 ADR 以设计原则（可观测性、可扩展性）为起点，从原则推出决策，不从实现倒推。判断标准：决策能否用"为了实现原则 A，需要机制 B"的链条表述
- **扩展性判据 = 新增关注点是否需要修改既有源码**：评估挂载/扩展机制时，硬判据是"新增一个关注点（脱敏、超时、指标）是否要改管线代码"。注册即扩展，枚举即修改
- **需求澄清是架构设计的一环**：术语未对齐前不谈决策；决策文档只写已拍板内容，讨论中间物（MVP 范围、顺序治理、阶段划分）一律剔除或显式标注"未决策"。判断标准：文档中每句决策性表述能否追溯到用户明确说过的话
- **概念争议以源码为准**：与用户对参照系统行为的记忆冲突时，读源码裁决，不采信任何一方（包括 AI 自己）的记忆

## 给后续 agent 的参考

- 涉及概念层架构决策时，先确认设计原则，再从原则推导方案，不要直接抛方案选项
- 评估扩展机制时，用"新增一个关注点是否要改既有代码"作为硬判据主动自检
- 写 ADR 前检查：每句决策性表述是否都能追溯到用户明确说过的话；未决策内容一律放"开放问题"并标注"禁止视为已定"，或直接剔除
- 引用 DHS 等参照系统的行为时，先读源码核实，不采信用户或自己的记忆；同时主动指出参照系统的弊端，不做单纯同构
