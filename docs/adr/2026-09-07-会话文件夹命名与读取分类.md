# 会话文件夹命名与读取分类决策

## 版本

| 版本 | 更新内容 |
| ---- | -------- |
| 1.0 | 创建文档初稿 |

## 问题界定

### 问题简述

SessionStore 需要把每个 session 的 jsonl 文件按所属项目（cwd）组织在会话根目录下。核心矛盾：项目路径包含 `/`、`\`、`:` 等不能直接用作文件夹名的字符，必须编码成一个文件夹名。编码必须保证不同项目路径不生成同一个文件夹，撞车会导致两个项目的会话混在一个目录里；同时 UI 全局视图启动时没有任何"当前项目"上下文，要建立"项目路径到会话列表"的分组。必须决策：命名规则和读取分类方法。

### 讨论范围

- `src/myagent/utils/helper.py` 的项目路径编码函数。
- SessionStore 读取侧按项目定位会话文件的方法。
- 会话根目录（`session_folder`）下的目录结构。

### 非讨论范围

- SessionPresist 写入侧落盘 cwd 的具体实现（本 ADR 只记录依赖，实现是后续任务）。
- SQLite 等新存储后端的引入（用户明确现阶段不引入）。
- 会话 jsonl 文件内部的格式（由 load 模块 docstring 与 2026-09-04 两级回滚 ADR 约定）。

### 问题深度

目录布局和读取路径是存储层的长期契约，改动需要迁移已有数据，属于基础结构决策。

## 现状

- `helper.py` 已实现 `project_path_to_session_folder`：分隔符替换为 `-`，追加 uuid5 前 8 位。
- 会话文件为 `{session_id}.jsonl`，第一行 meta 目前不含 cwd（store.py 注明"cwd 未落盘，暂恢复为空串"），meta 现有 session_id、name、created_at 等字段。
- SessionStore 的 load/fork 尚未实现，读取侧目录结构正是本次决策定下的。
- 调研结论：Claude Code 把所有非字母数字字符替换为 `-`，已被多个 GitHub issue 证实发生真实撞车（中文路径整体变成 `-`，不同项目共用目录，anthropics/claude-code #46071、#70674、#39528）；pi 用 `--路径--` 包裹、同为有损；Gemini CLI 用路径 SHA-256 哈希；Codex CLI 按日期存文件加 SQLite 索引；deepseek-harness 用 `~XXXX` 转义的 projectKey 加启动时全量扫描 header。

## 决策前提

- 前提 1（用户约束）：不同项目路径必须生成不同文件夹，撞车不可接受；名字可读性是次要目标。
- 前提 2（用户约束）：现阶段不引入数据库，也不引入注册表/索引文件等额外状态。
- 前提 3（用户确认）：读取分类暂不急需，先按临时方法实现，将来有需要再优化。
- 前提 4（事实，检索核实）：deepseek-harness 启动时全量扫描所有会话日志的第一行 header（含 cwd、标题、时间）建内存索引；UI 显示标题本来就要读 header，扫描不是额外开销；数千会话为毫秒级。
- 前提 5（用户决策）：文件夹名 = 路径分隔符替换为 `-` 加 uuid(cwd)[:8] 后缀；名字不可逆可接受，项目真实路径以 meta 的 cwd 为准。
- 前提 6（事实，代码现状）：meta 行当前未落盘 cwd；扫描方案生效的前提是写入侧先把 cwd 写进 meta。

## 可选方案

### 方案 A：有损名 + uuid 后缀（选定）

文件夹名 = 路径中 `/` `\` `:` 替换为 `-`，末尾追加 uuid5(规范化路径) 的前 8 位十六进制。读取分类仿照 deepseek-harness，全量扫描每个会话文件第一行 meta 的 cwd，组成 cwd 到 session 列表的映射。

**优势**

- 名字可读，实现只要几行代码。
- 唯一性不依赖编码规则本身，由 uuid 后缀兜底，绕开 Claude Code 式撞车的整类问题。
- 读取不需要维护任何额外状态文件。

**劣势**

- 名字不可逆，反查项目路径只能读 meta。
- uuid 后缀是 32 位空间，碰撞概率非零。
- 依赖写入侧落盘 cwd（当前未做）。

### 方案 B：可逆转义编码

先把路径中的 `-` 变成 `--`，再把 `:` `/` `\` 变成带标记的组合（如 `-c` `-s` `-b`），反方向解析可完整还原路径。

**优势**

- 名字即路径，零扫描、零额外文件即可建立 cwd 映射。

**劣势**

- 名字更长更难读。
- 对路径规范化（大小写、尾斜杠）要求严格，否则同一项目生成两个名字。
- UI 显示标题、时间仍要读文件，可逆只省掉一次启动扫描，收益小。

### 方案 C：纯哈希名（Gemini CLI 路线）

用路径的 SHA-256 哈希做文件夹名。

**优势**

- 碰撞概率可忽略，长度固定，在 Windows 上必然合法。

**劣势**

- 完全不可读，想知道文件夹对应哪个项目必须读文件。

### 方案 D：注册表文件或 SQLite 索引（Codex CLI 路线）

维护 index.json 或 SQLite 表，存文件夹名到项目路径的映射。

**优势**

- 全局视图零扫描，查询能力强。

**劣势**

- 多一份需要维护一致性的状态（并发写、崩溃恢复）。
- 用户明确现阶段不想引入。

## 决策逻辑

| 前提条件 | 对应方案 | 备注 |
|----------|----------|------|
| 前提 1 + 2 + 3 成立（当前状态） | 方案 A | 当前选择 |
| 会话数达到数千以上且启动扫描延迟不可接受 | 方案 D，先 index.json 后 SQLite | 备选触发条件 |
| 出现 uuid 后缀撞名的真实案例 | 加长后缀，并在读取时用 meta cwd 与所在文件夹比对、不一致报错 | 防御性补丁 |
| 需要零 IO 建立 cwd 映射且能接受长名字 | 方案 B | 备选触发条件 |

## 演进历史

| 版本 | 方案 | 解决的问题 | 引入的新问题 |
| ---- | ---- | ---------- | ------------ |
| v1 | 可逆转义编码 | 消除多字符映射到 `-` 的歧义 | 名字长；对规范化要求高 |
| v2 | deepseek-harness 式 projectKey（~XXXX 转义 + header 扫描） | 中文路径不撞名，名字可读 | 实现复杂度高于当前需要 |
| v3 | 分隔符换 `-` + uuid5[:8] + 扫描 meta（最终） | 简单、唯一性靠 uuid、读取无额外状态 | 名字不可逆；依赖 meta 落盘 cwd |

## 最终决策

当前成立的前提：前提 1、2、3、4、5、6。

因此选择 `方案 A`。

前提失效时的切换路径：见决策逻辑表。扫描成为瓶颈时切方案 D；uuid 撞名时加长后缀并补 meta cwd 校验；需要零 IO 映射时切方案 B。

## 决策原因

- 原因 1：唯一性由 uuid 后缀保证而不是编码规则，规避了 Claude Code 已发生撞车事故的整类问题，又不需要方案 B/C 的编码复杂度。
- 原因 2：读取分类与"显示标题必须读 header"复用同一次 IO，扫描没有额外成本，符合用户"这个问题暂不急需解决"的优先级判断。
- 原因 3：不引入注册表、索引或数据库，崩溃恢复需要考虑的状态最少，与用户当前约束一致。

## 后续影响

- 后续任务：SessionPresist 写 meta 时落盘 cwd（补齐前提 6）；SessionStore.load/fork 按新目录结构实现；UI 分组读取器（扫描 meta 组成 cwd 到 session 列表的映射）。
- 已知限制 1：文件夹名不可逆，反查项目路径只能读会话文件的 meta。
- 已知限制 2：uuid5 前 8 位是 32 位空间，2000 个项目时碰撞概率约万分之五；碰撞表现为两个项目共用目录，读取侧补 meta cwd 校验之前无法发现。
- 已知限制 3：Windows 路径大小写不做归一化，`D:\a` 和 `d:\a` 会生成两个文件夹。
- 已知限制 4：除 `/` `\` `:` 外的 Windows 非法字符（`< > " | ? *`）未处理，路径含这些字符时创建文件夹会失败。
- 已知限制 5：中文在文件夹名里保留原样，不同中文路径靠 uuid 后缀区分，人眼只看名字分辨不出相似路径。
