# 异常分类树新增策略域与未知域

## 版本

| 版本 | 更新内容 |
| ---- | -------- |
| 1.0 | 创建文档初稿 |
| 1.1 | 补记：兜底域类名后续落定为 `AgentUnclaimedError`（语义由"归因失败"改为"无人认领"），正文保留当时的命名以存史 |

## 问题界定

### 问题简述

当前异常分类树只有两个域：`LLMCallError`（LLM 调用路径）与 `ToolExecuteError`（工具执行路径）。但"由循环自身判定产生的错误"不属任一域——"达到最大步数"只能就地造 `RuntimeError`（既无类型、也无法 `except` 归域），"重试次数耗尽"虽由循环产生，却也不能算 LLM 调用失败。另有一个历史类型 `LLmError`，其语义是"`request/error` 无人认领"，属流程决策而非错误来源。三者都缺一个正确的归属。

### 讨论范围

- 异常分类树的一级域按什么判据划分。
- 循环自身判定产生的错误归入哪个域。
- `LLmError` 如何处置。
- 新域的范围边界（窄 vs 宽）。

### 非讨论范围

- 错误处理本身：重试策略注册表条目、终止判定、恢复流程——后续统一处理。
- 各域的二级子类完整清单。
- 是否给既有 `LLMCallError` / `ToolExecuteError` 回补统一前缀。

### 模糊信息的明确定义

- **域**：异常分类树的一级节点，表示"错误在哪条路径上被产生或终结"。
- **策略判定**：由循环自身按配置/预算做出的判定（如达到步数上限、重试次数上限），触发条件完全由我方确定。
- **归因失败**：异常已捕获，但无法判定它属于哪个已知域。

### 问题深度

涉及异常分类树的一级划分判据（架构原则层面），影响全项目 `except` 的可判别性与后续错误处理的落点，属长期维护方式决策。

## 现状

- 既有树（2026-09-09 ADR）已定"按来源分类 + 重试策略剥离到独立策略注册表"，并明确"具体子类清单留待后续"；llm 域子类已落 execption.py。本 ADR 属该预留项的落实。
- 现有域只有两个：`LLMCallError`、`ToolExecuteError`。
- 循环自身判定的错误无归处：步数上限就地造 `RuntimeError`；重试上限由重试处理器汇总产出。
- `LLmError` 现语义为"`request/error` 无人认领"（流程决策）；而 2026-09-15 的 session 错误记录 ADR 已定"无人认领属决策、不占 `error_type` 位置"。
- `ToolRegister.execute` 已把普通工具异常兜成 `ToolResult`，故从 TaskGroup 冒出的**非熔断**异常通常不是"工具报告了一次失败"，而是编排层意外。

## 决策前提

前提是**当前成立的事实与约束**（非决策内容）；它们成立才推出本决策，失效则应切换方案（见"决策逻辑"）。

- 前提 1（既有约束，2026-09-09 ADR）：异常分类树按"来源"而非"错误处理"划分，重试策略独立在注册表——避免"处理方式一变就要动类型树"的耦合。
- 前提 2（现状事实）：现有域仅两个，循环自身判定的错误无归处——步数上限只能就地造 `RuntimeError`，既无可 `except` 的类型，也产不出 `error_type`。
- 前提 3（现状事实）：重试上限的终态由 loop 侧产生，但根因在 LLM 侧。
- 前提 4（现状事实）：从 TaskGroup 冒出的非熔断异常多为编排层意外，而非工具侧报告的失败。
- 前提 5（现状事实 + 既有决议）：`LLmError` 的旧语义（无人认领）属流程决策；2026-09-15 session 记录 ADR 已定它不应占 `error_type` 位置，故旧语义无存续必要。
- 前提 6（现状事实）：命名存在混淆风险——`LLmError`（拼写少一个 C）与新域风格不一致，易误读。
- 前提 7（需求约束，2026-09-15 ADR 前提 1/10）：session 的 `error_type` 需可读、可判别、可粗粒度过滤。因此每个域必须"可枚举、判据唯一"。

## 可选方案

### 方案 A：新增窄策略域 + 未知兜底域（选定）

- 新增 `AgentPolicyError`：只装"循环自身策略判定的终态"，首批子类 `MaxStepsExceededError`、`RetryExhaustedError`。
- `LLmError` 换职务改名 `AgentUnknownError`：语义改为"归因失败"的兜底。
- 一级域判据固化为"错误在哪条路径被产生/终结"。

**优势**

- 每个域可枚举、判据唯一（满足前提 7）：看到 `AgentPolicyError` 即知"必是某个策略判的"。
- 循环自身判定的错误有了归处，不再就地造 `RuntimeError`。
- 兜底与确定域分离，兜底不会污染策略域的判别力。

**劣势**

- 一级域从 2 个增至 4 个，读者需理解"域 = 终结路径"这一判据。
- `LLmError` 改名波及 loop 抛错点、`turn` 的 except 与测试引用。

### 方案 B：新增宽域 `AgentOrchestrationError`（否决）

把"策略判定"与"编排层未归因异常"一并装进一个域。

**劣势**：混入兜底性质，该域失去"可枚举"（违反前提 7）；将来看到该类型无法判断是"策略判的"还是"没归因的"，判别力被摊薄。

### 方案 C：不新增域，塞入既有域（否决）

把步数/重试上限塞进 `LLMCallError` 或 `ToolExecuteError`。

**劣势**：污染既有域语义（它们既不是 LLM 调用失败、也不是工具执行失败），与前提 1 冲突。

### 方案 D：不新增类型，沿用 `RuntimeError` / 裸 str（现状，否决）

**劣势**：无类型即无法归域（前提 2），也产不出 `error_type`（前提 7）。

## 决策逻辑

| 前提条件 | 对应决策 | 前提失效时的切换 |
|----------|----------|------------------|
| 前提 2：循环自身判定的错误无归处 | 新增独立域 | — |
| 前提 7：`error_type` 需可枚举、可判别 | 域取**窄**——只装策略判定；未归因走兜底 | 若"策略判定"的边界将来模糊化 → 需重新划分域 |
| 前提 3：重试上限产生者在 loop、根因在 LLM | 归策略域，并以 `from last_llm_error` 保留根因（域信息由异常链承载） | 若该终态改由 LLM 层产出 → 应归 LLM 域 |
| 前提 4：非熔断 group 多为编排意外 | 先尝试归因：内层若已是已知类型则按原类型抛；归不了 → `AgentUnknownError` | 若工具层改为用异常承载失败 → 应归工具域 |
| 前提 5：无人认领旧语义无存续必要 | `LLmError` 换职务为 `AgentUnknownError` | 若仍有调用方依赖旧语义 → 保留过渡别名 |
| 前提 6：命名易混 | 新类型统一 `Agent*` 前缀 | 是否回补既有两域前缀，另行决策 |

## 最终决策

当前成立的前提：前提 1~7。

因此确定：

- **一级域判据** = 错误在**哪条路径上被产生或终结**；域内二级按原因细分。
- 新增 `AgentPolicyError`（继承 `MyAgentError`）：装循环自身策略判定的终态；首批子类 `MaxStepsExceededError`（步数上限）、`RetryExhaustedError`（重试上限）。
- `LLmError` 改名 `AgentUnknownError`，语义改为"归因失败的兜底"；承接编排层未能归因的异常。
- 非熔断 `ExceptionGroup` 的处置：先拆包并按内层类型归因；内层不属已知类型时才归 `AgentUnknownError`。
- 本次只定**类型树的域与归属**，不含错误处理（策略注册表条目、终止判定留待统一设计）。

前提失效时的切换路径：见决策逻辑表。

## 决策原因

- 原因 1：前提 2 下，循环自身判定的错误必须有归处——就地造 `RuntimeError` 既不可 `except` 归域，也产不出 `error_type`。
- 原因 2：前提 7 下，域必须保持"可枚举、判据唯一"，故策略域取窄、兜底另立（对比方案 B）。这是与"宽域"方案的关键分野。
- 原因 3：前提 3 下，重试上限按"**产生者**"归策略域是安全的——根因不会丢：只要用 `from` 挂上最后一次 LLM 错误，2026-09-15 session 记录 ADR 定下的异常链文本就会把它带出来。
- 原因 4：前提 5 下，`LLmError` 的旧语义已无处安放（无人认领属决策），换职务为兜底是顺水推舟，而非新增负担。
- 原因 5：前提 1 下，本次是 2026-09-09 ADR 预留项的落实，不改变"按来源划分 + 策略剥离"的既定方向。

## 后续影响

- 改名波及：loop 的 `raise LLmError(...)`、`turn` 的 except 引用、测试引用需同步。
- 落地：步数上限从就地造 `RuntimeError` 改为抛 `MaxStepsExceededError`；重试处理器产出 `RetryExhaustedError` 并 `from` 最后一次 LLM 错误。
- 策略注册表需为 `AgentPolicyError` 补条目（语义上应"不重试"）——属错误处理范畴，另行处理。
- 是否给 `LLMCallError` / `ToolExecuteError` 回补 `Agent*` 前缀以统一风格，另行决策。
- 各域的二级子类清单仍不完整；发现新来源时按本次判据补充。
