# judge 输出未抽象化

## 版本

| 版本 | 更新内容 |
| ---- | -------- |
| 1.0 | 创建文档初稿 |

**状态**：acknowledged

## 问题描述

judge 的输出没有抽象化：每次要加一个输出字段，都需要「改头（prompt）改尾（解析输出和使用）」两处同步。

本次要给 judge 加 `score` 输出，暴露的改动面即如此：

- **改头**：`judge_agent.py` 的 `Judge_prompt` 里输出格式段是写死的 `{"pass": ..., "reason": ...}`。
- **改尾**：解析输出与使用输出的地方都要跟着改。

对照之下，`case.yaml` 里加评分标准这一步是**解耦的**，不受此限制影响。

## 相关代码位置

| 环节 | 位置 |
| ---- | ---- |
| 提示词（头） | `src/lifeprismevalue/agent/judge_agent.py` 的 `Judge_prompt` |
| 解析（尾） | `src/lifeprismevalue/evalue/case.py` 的 `_parse_verdict` |
| 使用 / 落载荷（尾） | `src/lifeprismevalue/evalue/case.py` 的 `_run_judge`、`_result` |
| 汇总（尾） | `src/lifeprismevalue/evalue/runner.py` 的 `CaseResult`、`_build_result`、`SUMMARY_COLUMNS`、`_summary_row` |
